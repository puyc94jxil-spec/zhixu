# 生成中删除后的占位句

独立 TEST 在 `6265ee4` 上关闭了取消缺陷和页面缺陷。这个关闭不推广到别的提交。他们另外看到：生成过程中删除依据文件后，回答是 `withdrawn`，正文里没有原来的句子，但没有契约里的删除占位句。正式抓包还没回到本岗。下面只核对仓库里的契约草稿和当前代码，并在同一产品代码上重跑了一条已有回归。

契约是 `docs/constraints/DOC-ZHIXU-IMPL-CONTRACT-001-v0.1-draft.md`。

## 契约实际要求哪一层

- 第 8 节的 `done` 事件只要求 `request_id`、`message_id`、`status`，撤回时可以带 `withdrawal_reason`。事件格式里没有正文，也没有要求把占位句放进事件。
- 第 10 节要求已经流出的临时文字在界面和持久记录里改成撤回或未核验，不能再标成已完成且已引用。
- 第 11 节把占位句「[依据文件已删除或撤销，该轮材料内容不再纳入上下文]」写在构造发给模型的历史消息上。用户自己的问题可以保留。已经到达客户端的增量，要求发出撤回事件，并承认用户可能已经看见片段。
- 偏差记录里多做了一层：在线读取会话时，来源已删除的助手正文也换成这句。这比契约更严，继续保留。

## 三层现在各是什么

| 层 | 现在的行为 | 这次怎么看 |
| --- | --- | --- |
| 实时界面 | 增量先显示在当前气泡里。`done` 只把状态改成撤回，气泡文字要等随后重新打开会话才换成持久正文。 | 刷新前仍可能看见已经到达的片段。这是契约写明的残留，不是把占位句从持久记录里拿掉。 |
| 持久历史 | 删除原因是 `source_deleted` 时，助手消息正文写成占位句，引用被清掉。在线读取时如果来源已删除，也会再换成这句。 | 会话接口读到的是占位句，不是空字符串，也不是原句。 |
| 回放给模型 | 下一次组上下文时，来源已删除的助手消息换成同一句占位，不附带已删文件的分块。 | 契约要求的就是这一层。 |

事件流里的增量会被清空，所以重放事件时看不到原句，也看不到占位句。这和 `done` 事件的字段一致，不把它当成缺了一句契约正文。
