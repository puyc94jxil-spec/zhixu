## 4. 既有原型对照与需求差异（须进审批）

既有实现见 [实现计划第 7–9、17–19 行](https://github.com/puyc94jxil-spec/zhixu/blob/ac62ee813425b2a8494324ae9cb28585e1303e29/docs/plans/2026-11-23-zhixu-implementation.md#L7-L9)：无构建 HTML/CSS/JS；localStorage；File API 本地读取；固定示例回答。使用说明与需求第 139 行确认：无模型 API、不上传服务器、无真实账号或跨设备同步；PDF/DOCX 仅元数据；示例引用只对内置报告。

本候选相对该原型的关键差异（均为人工审批项）：

- 新增服务端，会话与文件以服务端为准，不再以浏览器 localStorage 为权威数据。
- 浏览器只调用本后端；由后端访问 Qwen，真实流式生成，不再使用固定模拟作为验收通过证据。
- 用户文件上传至服务端私有存储并解析、索引；产生真实可回溯引用。
- 引入账号登录、会话鉴权与按用户隔离。
- 前端在既有页面信息架构上演进，但数据源改为后端 API / SSE。

**保留既有原型以便比对：** 源仓当前 `index.html`、`styles.css`、`app.js` 及 `output/` 截图、使用说明与验证记录在实施中应原样保留（建议另置 `prototype/` 快照或保持根目录只读对照，不把原型改写成唯一生产入口）。生产界面可复制后改造，对照演示回答与真实回答。

## 5. 单一技术方案（候选，未批准）

## 6. Qwen OpenAI 兼容调用与 SSE 适配（DES-ZHIXU-MODEL-001）

### 6.1 调用方式

- 服务端使用 OpenAI 兼容 Chat Completions：`POST http://192.168.2.46:9938/v1/chat/completions`，请求含 `model=Qwen3.8-27B`、`stream=true`、`messages`（系统/开发约束 + 本会话多轮 + 可选检索块）。认证放在服务端上游请求头，从不返回给浏览器。
- 产品侧：浏览器只对**本后端** `POST /conversations/:id/messages` 取得 `request_id`，再 `GET /requests/:id/events` 消费 SSE；或等价的已鉴权 SSE 连接。取消走 `POST /requests/:id/cancel`。

### 6.2 增量解析、结束、引用核验与取消

- 后端按行解析上游 `text/event-stream`（`data: {...}` 增量，`data: [DONE]` 结束；若该服务使用不同但兼容的流式分帧，适配器须将其归一）。将 `choices[].delta.content`（或兼容字段）映射为产品事件 `delta`。
- **临时生成与已核验引用必须区分。** 流式过程中的文字与待绑定出处一律视为临时/未校验，界面须标明未核验；**未通过校验的引用不得作为可点击的可信引用展示。** 仅在服务端完成结构化核验后，才能发出最终 `citation` 并进入可点击回溯。
- 文档问答须将材料性结论**逐条**绑定到具体 `chunk`（file_id、version、page/paragraph）与 `quote`。无检索命中则不进入「有依据材料结论」，最终说明使用「资料中未找到」。
- 核验失败时，**不得**只删除引用却保留无依据结论：须阻止该条材料结论最终化，或明确撤回为「资料中未找到」。已向用户流出的临时文字须改为撤回/未核验状态，不得以「完成且已引用」收口。
- 引用的字符串命中（quote 在对应 chunk 文本中可定位，允许有限空白差异）**只证明可溯源，不能证明语义支持**。幻觉与支持性须用真实中文样例集验收（C 期采集，未测不得宣称通过或「已杜绝错引」）。
- 正常结束发 `done`（仅当材料结论已按上款最终化或已撤回）。上游错误或本端校验失败发 `error`（可区分超时、断网/不可达、限流），**不得**把失败写成已完成（Q07）。
- 取消：本端中止上游 HTTP、停止继续推送增量，消息状态为中止（Q02），取消须幂等。取消或删除发生时的竞态与「部分输出可能已到达客户端」的残留风险见第 8 节，须真实验证，不能仅靠设计断言已消除。

### 6.3 超时、重试与错误映射（数值均为候选目标，未实测，非源需求强制值）

源文第 129–130 行为「拟定目标及验证方式」（首字响应普通文本问题 P95 ≤ 5 秒，前提为模型与网络固定），须结合部署验证，**不能当作已承诺或已测达标**。下列运行参数是为可实施而给出的**候选目标**：

| 参数 | 候选目标（未实测） | 说明 |
| --- | --- | --- |

## 7. 文档上传、解析、检索与引用（DES-ZHIXU-DOC-001 / SEC-001）

- **格式与提取库：** 以第 63 行为准，P0 为可提取文字的 PDF、DOCX、TXT、MD。其他扩展名在提交前拒绝。PDF 唯一建议提取库为 **pypdf**，DOCX 为 **python-docx**（许可证/依赖审查未做，标候选）。PDF 若无可提取文字（扫描件），P0 提示「不含可提取文字」，不进入可分析状态，**不做 OCR**。
- **限额（源文为「建议」，本包作可批准默认）：** 单文件 20MB，单会话 5 个，总量 50MB，PDF 200 页；超限提交前说明，未超限文件可继续。
- **安全与隔离：** 扩展名与探测到的内容类型双重检查；存储私有。解析必须在**非特权独立子进程**中运行：无网络、仅受限目录、限制 CPU/内存/解压体积与超时（候选建议：单文件解析墙钟 120 秒、解压/展开体积不超过原文件 10 倍——**建议值，源文未给数字，未实测**）。**工作线程不是隔离边界。** 任务状态写入 **SQLite 任务表**并可在中断后恢复，不能仅内存排队。加密 PDF、损坏、空文档分别失败原因；任务可取消且幂等（以 file_id+content hash+version 去重提醒，D08）。
- **切块：** 按标题/段落/页切分；每块必须有 file_id、version、page 或 paragraph、offset、text。解析缺页须在状态或摘要中提示（D07）。
- **检索：** 入库与查询均须经统一 **jieba** 分词后再进入 FTS5（强制，非可选）。chunk 保留原文页/段/offset 映射。仅在本会话 `ConversationFile.enabled=true` 的文件版本上检索。移除或禁用后，后续请求不得再读该文件（D04）。检索质量以真实中文样例集量测；不宣称优于向量、不宣称可杜绝错引。
- **引用纪律：** 模型提示中明确：只根据给定块作答；材料性结论须逐条绑定 chunk 与 quote；禁止编造金额、日期或出处。流式阶段的出处为临时态，**未校验引用不可做可点击可信引用**。最终化前检查每条绑定：quote 须能在对应版本 chunk 中定位（允许有限空白差异）。该检查只证明可溯源，不能证明语义支持。失败时阻止该材料结论最终化，或明确撤回为「资料中未找到」，**不得**只删引用而保留无依据结论。预览与最终输出前须重校验 file 版本、owner 与删除标志；点击须打开**同一版本**并高亮，失败时仍展示出处，不跳无关页。幻觉/支持性须用真实样例验收。
- **隔离 / 鉴权：** 预览、状态、下载、检索、引用及最终输出前均校验 owner、会话授权、文件版本与未删除标志，禁止枚举 ID 越权（第 119 行）。已删除或已撤销授权的数据不得继续经在途生成、预览或引用泄出。
- **日志：** 默认不写文档全文、提示全文或密钥。
